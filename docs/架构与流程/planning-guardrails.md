# 旅行规划守卫规则

本文记录旅行社 RAG（检索增强生成）、真实工具调用和最终报告生成的运行边界，避免模型在信息不足时提前查库存或生成正式交付物。

## 日期与真实查询

- 用户没有明确或确认出发日期时，需求状态只能写“日期待确认”。
- 可以在预算或行程草案中写“暂按某日期待核验估算”，但不能把该日期用于真实交通、酒店或票务查询。
- 真实交通、酒店、票务查询必须满足日期前置条件：`departure_date` 是 `YYYY-MM-DD`，且 `departure_date_confirmed` 不是 `False`。
- 如果工具收到未确认日期，工具层会跳过调用并返回需要先确认日期的提示，避免生成航班、车次、酒店库存或价格。

## 旅行社省心方案

- 用户明确要求旅行社省心方案、成熟路线、产品路线或顾问方案时，先匹配内部产品/路线模板。
- 首轮产品表达只给 2-3 个方向，说明适用人群、服务边界和报价口径。
- 内部资料只作为方案依据，不承诺已成团、已占位、已锁价或可支付。
- 用户明确拒绝旅行社产品后，切回自由规划，不继续主动推省心方案。

## 最终报告门禁

最终 `report_data` 和最终报告卡片只能在以下关键项已确认后生成：

- 目的地和明确日期。
- 交通方案。
- 住宿方案或住宿类型。
- 完整行程。
- 预算汇总。

如果仍处于目的地推荐、产品框架或路线候选阶段，即使用户说“生成最终报告”，也只说明缺口并继续补齐，不调用 `generate_order_tool`。
