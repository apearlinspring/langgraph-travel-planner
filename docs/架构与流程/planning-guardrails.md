# 旅行规划守卫规则

本文记录旅行社 RAG（检索增强生成）、真实工具调用和最终报告生成的运行边界，避免模型在信息不足时提前查库存或生成正式交付物。

## 日期与真实查询

- 用户没有明确或确认出发日期时，需求状态只能写“日期待确认”。
- 可以在预算或行程草案中写“暂按某日期待核验估算”，但不能把该日期用于真实交通、酒店或票务查询。
- 真实交通、酒店、票务查询必须满足日期前置条件：`departure_date` 是 `YYYY-MM-DD`，且 `departure_date_confirmed` 不是 `False`。
- 如果工具收到未确认日期，工具层会跳过调用并返回需要先确认日期的提示，避免生成航班、车次、酒店库存或价格。
- 聊天快路径可以把“下周一”等相对日期解析成结构化事实并暂存到 `fast_mode_split`，但仍要在用户确认或补齐基础事实后才进入正式报告或真实查询。

## 旅行社省心方案

- 用户明确要求旅行社省心方案、成熟路线、产品路线或顾问方案时，进入 `active_workflow=agency_plan`，用 `agency_step` 推进独立省心方案工作流。
- 省心方案固定节奏是：基础需求 -> 产品匹配 -> 方案草案 -> 用户评价/微调 -> 报告。
- 基础需求阶段只确认目的地、天数、人数、预算、出发地和日期等关键事实；缺一两项时一次只追问最影响方案的一项。
- 基础事实足够后，优先匹配内部产品/路线模板，输出成熟路线样板，而不是像自由规划一样追问交通方式或酒店偏好。
- 首轮产品表达只给 1-2 个清晰方向或一版方案草案，说明适用人群、涵盖服务、费用说明和报价口径。
- 内部资料只作为方案依据，不承诺已成团、已占位、已锁价或可支付。
- 用户明确拒绝旅行社产品后，切回自由规划，不继续主动推省心方案。
- 省心方案默认不调用 `query_transport_options`、实时酒店搜索、`select_transport_tool`、`select_accommodation_tool`；如果模型误调，中间件应拦截或从工具白名单移除，避免漂回自由规划阶段。

## 意图分流快路径

- 首轮已经包含目的地、天数、人数、预算或日期等旅行需求，但未选择模式时，后端先本地返回一句自然分流文案，不创建完整 Travel Agent（旅行智能体），不加载 MCP（模型上下文协议）工具。
- 分流文案必须承接目的地，避免干巴巴只问二选一；例如“杭州很适合慢逛和尝鲜，四天左右刚好能把西湖和老城区走舒服。您想要现成省心方案，还是个性化旅游规划？”
- 方向语义优先于地名首次出现：`从A去B`、`A到B`、`A -> B` 中 A 是出发地，B 是目的地。
- 快路径解析出的事实写入消息 `extra_info.fast_mode_split`，下一轮用户选择模式或补日期时自动合并，不要求用户重复首句信息。

## 最终报告门禁

最终 `report_data` 和最终报告卡片只能在以下关键项已确认后生成：

- 目的地和明确日期。
- 交通方案。
- 住宿方案或住宿类型。
- 完整行程。
- 预算汇总。

如果仍处于目的地推荐、产品框架或路线候选阶段，即使用户说“生成最终报告”，也只说明缺口并继续补齐，不调用 `generate_order_tool`。

省心方案报告也必须遵守门禁。成熟路线样板可以先展示，但正式报告仍需补齐关键事实，并在费用、门票、交通和住宿处标注参考价、采集口径、待核验和不锁价。

## 慢响应与降级

- 完整 Agent 流存在事件空闲超时保护；模型或上游长时间没有任何事件时，后端返回可恢复兜底回复，并保留已确认状态。
- 首轮分流、模式确认和省心方案基础事实补齐应优先走本地快路径，避免无意义加载外部 MCP 工具。
- 首轮分流后的模式确认必须把快路径解析出的出发地、目的地、日期、天数、人数和预算注入本轮状态；后续工具如果没有返回需求、模式或进度字段，不能用空快照覆盖“省心方案”和已确认信息。
- 地图或外部查询超时不能让前端长时间卡在“正在准备”；应进入可读降级态，说明暂未定位或待核验。
