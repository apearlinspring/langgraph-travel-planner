# Step Prompt Rule Inventory（阶段 Prompt 规则清单）

本文整理 `app/agents/handoffs/step_config.py` 里仍以内联 Prompt 承载的硬规则、工具边界和用户可见红线。它不是新的业务入口，而是把当前规则先显性化，方便后续外移到 schema（结构化规则定义）或 spec（规则规格文件）时逐条迁移。

## 维护边界

- 当前事实来源仍是 `step_config.py`、`app/core/workflow.py` 和 `app/core/middleware.py`。
- 本文只记录公开工程口径，不包含本地运行证据、真实供应商库存、真实客户信息或真实密钥。
- `step_config.py` 是静态阶段配置；运行时工具开放还会被 `StepConfigMiddleware` 和工具自身守卫继续收紧。
- 修改阶段 Prompt、工具列表、状态字段或报告门禁后，应同步更新本文和 `tests/test_step_prompt_rendering.py` 的规则保护测试。

## 自由规划阶段规则

| 阶段 | Prompt 硬规则 | 工具边界 | 用户可见红线 |
|---|---|---|---|
| `requirement_collection` | 自然聊天收集出发地、日期、天数、人数、预算、风格和特殊需求；一次只问 1-2 个问题；长期记忆只写稳定偏好、长期禁忌和历史旅行。 | 可记录需求、确认规划模式、写证据包和长期偏好；可在明确路线图诉求时生成可视化旅程草案。 | 不暴露步骤、字段、工具名或内部知识库；日期不明确时不能触发真实交通、酒店或票务查询。 |
| `destination_recommendation` | 已指定目的地时先做季节、预算和适配校验；未指定目的地时给 3-5 个候选并解释理由；用户确认后才记录目的地。 | 默认只对主推目的地做一次目的地信息查询；可用公开攻略和内部旅行社知识辅助。 | 不把内部知识说成真实库存；不在产品框架阶段生成最终报告卡片。 |
| `transport_planning` | 用户明确交通方式或要求真实查询时，先检查出发日期是否明确或已确认；没有明确偏好时才问 1-2 个偏好问题。 | 日期确认后才开放 `query_transport_options`；记录交通方案走 `select_transport_tool`。 | 日期待确认时不得查真实航班、车次或票务；不编造班次、价格和余票。 |
| `accommodation_planning` | 先确认住宿偏好、区域、档次和特殊需求；有真实查询诉求时也要先检查日期。 | 日期确认后才开放真实酒店查询；住宿选择由 `select_accommodation_tool` 写入结构化状态。 | 不承诺酒店库存、房型、早餐权益、价格或锁价；临时住宿偏好不写长期记忆。 |
| `food_planning` | 按旅行风格、人群和禁忌推荐餐饮方向；长期饮食偏好和禁忌才写记忆。 | 记录餐饮选择，必要时写长期饮食偏好。 | 不把本次口味要求写成长期画像；不推荐与禁忌冲突的餐饮。 |
| `itinerary_generation` | 生成 Day 1 / Day 2 格式行程，天数必须与需求一致；草案确认后必须调用结构化行程工具。 | `generate_itinerary_tool` 写入最终 itinerary；景点价格和内部知识只作依据。 | 缺交通、住宿或价格来源时写“待二次核实”，不编造班次、酒店或票价。 |
| `budget_summarization` | 用户要求预算或进入预算阶段时必须写入结构化 budget；可见回复保留预算明细、预算匹配、费用依据、关键假设、预算置信度和待核验项。 | `summarize_budget_tool` 是预算阶段主工具；除非用户明确要求最终报告或支付，不继续生成订单。 | 预算是估算；必须区分已确认价格、估算价格和待核验价格，不写成真实锁价。 |
| `order_generation` | 只有交通、住宿、完整行程和预算都确认后，才调用 `generate_order_tool`；报告保持结构化章节，便于前端渲染。 | 可生成订单/报告，也可回退到目的地、交通、住宿、餐饮、行程或预算。 | 不编造支付链接、客服、优惠活动、真实库存、票价、房态或已预订结果。 |

## 省心方案公共规则

省心方案使用 `agency_step` 推进独立工作流，不走自由规划的交通、住宿、餐饮逐项确认链路。公共规则当前通过 `agency_common_prompt` 注入所有省心阶段：

- 固定节奏：基础需求 -> 匹配方案 -> 方案草案 -> 用户评价 -> 报告。
- 基础需求只确认目的地、天数、人数、预算、出发地和出发日期。
- 成熟路线样板优先，输出产品化方案，而不是追问交通方式或酒店偏好。
- 方案草案必须包含交通口径、住宿区域/档次与示例酒店、景点门票参考、餐饮安排、费用说明、涵盖服务和待核验项。
- 主结构避免 Markdown 表格，优先使用短标题、分组要点和 Day 1 / Day 2 列表，方便前端卡片渲染。
- 内部产品模板、服务 SOP（标准作业流程）、报价规则、风险手册和报告标准只能支撑方案依据，不能被包装成真实库存、已成团、已占位、已锁价或可支付。

## 工具开放与禁止规则

| 场景 | 默认开放 | 默认禁止或收紧 |
|---|---|---|
| 自由规划需求收集 | 需求记录、模式确认、证据包、长期记忆工具。 | 不做真实交通、酒店、票务查询；不生成正式报告。 |
| 自由规划目的地推荐 | 目的地查询、目的地选择、景点价格、RAG 工具。 | 用户未确认目的地前不调用 `select_destination_tool`；同轮避免重复查询。 |
| 自由规划交通/住宿 | 日期确认后开放真实交通或酒店查询；确认后写入选择工具。 | 日期待确认时不开真实查询；同轮已查过时不重复查。 |
| 自由规划行程/预算/报告 | 行程、预算、最终报告工具按门禁推进。 | 关键事实缺失时不跳步生成 report_data 或最终报告卡片。 |
| 省心方案基础与匹配 | 需求记录、证据包、景点价格、内部产品/RAG 工具。 | 默认不开放 `query_transport_options`、`query_hotel_options`、`select_transport_tool`、`select_accommodation_tool`。 |
| 省心方案草案/反馈/报告 | 结构化行程、结构化预算、报告生成和内部证据工具。 | 不漂回自由规划交通/住宿/餐饮逐项追问；不把样板价覆盖用户预算。 |

如果用户在省心方案里明确要求“查真实航班/高铁/酒店价格/库存”，运行态可临时开放对应查询，但仍必须经过日期、库存、价格和待核验守卫。

## 报告、报价与库存红线

- 最终报告和 `report_data` 只能在目的地、明确日期、交通方案、住宿方案或住宿类型、完整行程和预算汇总具备后生成。
- 省心方案也必须遵守最终报告门禁；成熟路线样板可以先展示，但不是正式报告。
- 报价必须写清费用包含、不包含、关键假设、置信度和待核验项。
- 任何预算、样板价、门票、酒店和交通价格都必须保留估算、参考、采集口径或待核验边界。
- 不承诺真实支付、真实预订、真实供应链下单、已占位、已成团、已锁价、真实库存或履约成功。
- 外部 API（应用程序接口）、MCP（模型上下文协议）或 RAG（检索增强生成）失败时，只能输出可解释降级和“待二次核实”，不能补编事实。

## 外移路线

1. **规则枚举化**：为阶段规则建立稳定 ID，例如 `prompt.free.transport.date_required`、`prompt.agency.no_free_chain`、`report.no_payment_link`。
2. **schema 化**：把每个阶段的 prompt、allowed_tools、blocked_tools、requires、visible_boundaries 和 report_gate 拆进 YAML/JSON 规格，`step_config.py` 只负责加载和拼接。
3. **中间件共用规则**：让 `StepConfigMiddleware` 读取同一份 blocked_tools 和 report_gate，避免 Prompt 写了规则但运行态未执行。
4. **工具层守卫复用**：真实交通、酒店和订单工具复用日期、库存、锁价、支付边界，返回结构化 skipped/blocked 原因。
5. **测试生成化**：从 schema 自动生成规则存在性测试，继续保留少量手写回归测试覆盖省心方案不漂回自由规划、最终报告不承诺支付/预订/锁价。
6. **文档同步**：外移完成后，本文改为规则索引，正式事实来源切到 schema/spec，并在 `docs/架构与流程/planning-guardrails.md` 保留运行边界说明。

## 当前测试保护

`tests/test_step_prompt_rendering.py` 已覆盖以下低风险静态保护：

- 所有 `PLANNING_STEPS` 和 `AGENCY_STEPS` 都有 prompt 和 tools。
- 省心方案 prompt 明确不走自由规划逐项确认链路。
- 省心方案默认工具不开放实时交通、实时酒店、交通选择和住宿选择。
- 关键红线词保留：待核验、不锁价、不调用实时交通查询、不使用 Markdown 表格主结构。
- 最终报告 prompt 保留不编造支付链接、真实库存、票价、房态、跳过预算或锁价承诺的边界。
